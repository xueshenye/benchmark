# 云服客服工单系统

你好,我是云服客服团队的老张。我们团队每天要处理几十个客户问题,现在全靠一张 Excel 表记工单,翻起来太费劲了,还容易丢。想请你给我们做一个内部用的工单系统,真实能用的那种。

## 背景

- 客服同事接到客户报障(登录问题、支付问题、物流问题、发票问题等),需要在系统里登记一张工单。
- 工单要能被人跟进:处理到哪一步、谁在处理、要不要升级。
- 数据不能丢:工单记录要能长期保存,服务重启了也还在。
- 我们不是程序员,具体怎么实现你看着办;拿不准的,直接问我。

## 你手上有什么(/workspace 下)

- `docs/api.md`:技术团队给的一份接口约定(字段、状态流转、接口路径、统计)。**按这份约定做**,我们的系统要和它一致。
- `docs/tickets_export.json`:从旧 Excel 导出来的一批历史工单,给你参考字段和风格(不需要导入系统)。

## 工单业务上长什么样

- 一张工单记录一个问题:标题、描述、客户(报障人)、状态、优先级、指派客服、创建时间、解决时间。
- 状态:待处理 → 处理中 → 已解决 → 已关闭;已解决/已关闭的工单可以重新打开。
- 优先级:高 / 中 / 低。
- 客服要能搜索工单、按状态/优先级/负责人筛选、把工单指派给某个人。
- 工单处理太久没解决的,系统要能标出来(超时)。具体多久算"太久",我们业务上再定。
- 系统要有个网页,客服打开就能看工单列表。
